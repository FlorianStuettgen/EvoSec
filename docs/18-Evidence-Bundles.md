# 18 — Evidence Bundles

## Purpose

A completed replay is delivered as:

```text
output-directory/
├── report.json
├── report.md
└── manifest.json
```

`report.json` is the machine contract. `report.md` is the analyst surface. `manifest.json` commits to the artifact bytes and repeats the execution identities required to expose contradiction.

## Report contract 2.1

The report contains:

- engine and input provenance;
- compiled execution plan;
- one trace per rule;
- strict execution ledger;
- scenario context;
- summary counts;
- verification checks;
- ordered detections; and
- ordered simulated actions.

## Completion protocol

JSON and Markdown are written atomically first. The manifest is written atomically last. A manifest therefore marks a completed local bundle rather than an in-progress artifact pair.

## Standalone verification

```bash
soc-replay verify-bundle build/network-scan
```

Standalone verification does more than recalculate file hashes. It recomputes or cross-checks:

- exact top-level report and manifest field sets;
- report and manifest contract versions;
- engine, run, scenario, and provenance identity;
- run ID from the scenario schema version and input hashes;
- plan identity from the ordered rule fingerprints;
- candidate strategies from the declared index selectors;
- plan rule IDs and fingerprints against rule traces;
- per-rule trace totals against detections;
- detection IDs, correlation metadata, responses, and simulated actions;
- verification-check actual values and pass states from the detections;
- complete typed execution-ledger structure and hash chain;
- load, compile, evaluate, and verify stage digests and metadata;
- ledger stage counts against report contents;
- artifact names, byte counts, and SHA-256 hashes; and
- bundle ID derived from the canonical manifest body.

A modified, missing, partially written, structurally invalid, or internally contradictory artifact produces a failed verdict.

## Source-bound verification

```python
from soc_replay.report import verify_bundle

result = verify_bundle(
    "build/network-scan",
    source_directory="scenarios/network-scan",
)
raise SystemExit(0 if result.passed else 1)
```

Source-bound verification first performs every standalone check. It then reruns the supplied scenario with the installed engine and regenerates `report.json`, `report.md`, and `manifest.json`. All three generated byte streams must exactly match the bundle under review.

This closes the gap between self-consistency and source identity. A coherently rewritten field that is not independently derivable from the report alone, such as scenario presentation text, still fails when it does not reproduce from the supplied source directory.

Source-bound verification is intentionally strict. A bundle produced by a different engine version, toolchain behavior, or source byte stream will not reproduce exactly and therefore will not pass this mode.

## Adversarial contradiction tests

The test suite includes rehash attacks rather than only ordinary corruption:

- change a detection severity;
- recalculate the report artifact hash;
- recalculate the manifest bundle ID; and
- verify that recomputed verification values and ledger stage digests still reject the bundle.

A separate test performs a coherent report-only rewrite that remains internally consistent. Standalone verification accepts that limited case because no internal contradiction exists, while source-bound verification rejects it because the regenerated artifacts differ.

## Reproducibility

`tools/verify_deterministic_bundles.py` executes every maintained scenario twice in isolated directories, requires source-bound verification for both bundles, and compares all three artifact byte streams exactly.

## Security meaning

The ledger and manifest provide tamper evidence relative to their hashes. Source-bound verification proves agreement with the supplied scenario under the installed engine. Neither mode is a signature, trusted timestamp, external custody record, hardware identity proof, or proof of live telemetry provenance.

A party able to rewrite the bundle and the alleged source together can still create a new self-consistent evidence set. Authorship and external provenance require signing or independent attestation.
